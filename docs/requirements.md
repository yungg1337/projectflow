# Требования к модулям системы ProjectFlow

Документ описывает, что должна делать система, в соответствии с
ГОСТ 34.602-2020 (техническое задание) и ГОСТ 19.101-77 (виды программ).

## 1. Назначение системы

Система «ProjectFlow» нужна, чтобы вести проекты и задачи предприятия в одном
месте: назначать исполнителей, следить за сроками, видеть историю работы и
получать готовые отчёты. Сейчас такие сведения часто хранят в таблицах Excel и
в переписке, поэтому они быстро устаревают и теряются.

## 2. Роли пользователей

| Роль | Что может делать |
|------|------------------|
| Администратор | всё то же, что менеджер, плюс управление пользователями и ролями |
| Менеджер | создавать проекты и задачи, назначать исполнителей, принимать работу, формировать отчёты |
| Исполнитель | видеть свои задачи, переводить их в работу и отправлять на проверку, строить отчёты по своим задачам |

## 3. Требования к модулю авторизации (AuthModule)

1. Регистрация по адресу электронной почты, полному имени и паролю.
2. Адрес электронной почты не может повторяться (ответ 409).
3. Пароль не короче 8 символов и содержит буквы и цифры (иначе ответ 422).
4. Вход выдаёт access-токен на 30 минут и refresh-токен на 14 суток.
5. Забытый пароль восстанавливается по одноразовой ссылке, которая действует
   60 минут; ссылка записывается в файл `var/mail.log`.
6. Роли ограничивают доступ: закрытый адрес без нужной роли вернёт 403.
7. Администратор может заблокировать учётную запись и сменить роль.

## 4. Требования к модулю задач (TaskModule)

1. Создание, изменение и удаление проектов и задач.
2. Назначение исполнителя и установка срока (срок не раньше текущей даты).
3. Смена статуса только по правилам конечного автомата (см. `app/states.py`).
4. Каждая смена статуса попадает в историю: кто, когда и почему изменил.
5. Отклонение задачи требует комментария.
6. Фильтрация задач по проекту, исполнителю и статусу.
7. Проект с задачами удалить нельзя (ответ 409).

## 5. Требования к модулю отчётов (ReportModule)

1. Отчёт по исполнителю, по проекту и за период.
2. Выгрузка в PDF и Excel.
3. Сведения о сформированных отчётах сохраняются в базе.
4. Исполнитель получает отчёты только по своим задачам (иначе ответ 403).
5. Отчёт по проекту без задач формируется, процент выполнения равен нулю
   (деления на ноль быть не должно).

## 6. Требования к системе в целом

| Требование | Значение |
|------------|----------|
| Время ответа API | не более 0,5 с при 50 пользователях |
| Формирование отчёта на 1000 задач | не более 3 секунд |
| Покрытие кода тестами | не менее 85 % |
| Хранение паролей | только хэш PBKDF2-HMAC-SHA256 с солью |
| Защита адресов API | все адреса, кроме `/auth/*` и `/meta/*`, требуют токен |
| Запуск | одной командой `python run.py` |
| Зависимости | стандартная библиотека Python; `fpdf2` — только для PDF |

## 7. Порядок приёмки

1. Запустить приложение и войти под каждым из трёх пользователей.
2. Прогнать автотесты: `python -m unittest discover -s tests -t .`.
3. Проверить качество кода: `python tools/check.py` (замечаний быть не должно).
4. Создать задачу, провести её по всем статусам, убедиться, что запрещённый
   переход отклоняется.
5. Сформировать отчёты в PDF и Excel и открыть файлы.
