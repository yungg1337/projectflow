# ProjectFlow — система управления проектами

Учебное приложение для производственной практики ПП.02 (ПМ.02 «Осуществление
интеграции программных модулей»). Состоит из трёх модулей в одном приложении:

* **AuthModule** — регистрация, вход, восстановление пароля, роли;
* **TaskModule** — проекты, задачи, статусы, история изменений;
* **ReportModule** — отчёты и выгрузка в PDF и Excel.

Основная часть написана на стандартной библиотеке Python, поэтому приложение
лёгкое и запускается без сложной настройки. Единственная внешняя библиотека —
`fpdf2` — нужна только для выгрузки отчётов в PDF.

## Быстрый старт

```bash
python -m pip install -r requirements.txt   # нужен только для PDF
python run.py                               # сервер на http://127.0.0.1:8000
```

Откройте адрес в браузере. Демонстрационные пользователи:

| Роль | Логин | Пароль |
|------|-------|--------|
| Администратор | admin@example.com | admin12345 |
| Менеджер | manager@example.com | manager12345 |
| Исполнитель | executor@example.com | executor12345 |

Полезные параметры запуска:

```bash
python run.py --port 9000     # другой порт
python run.py --reset         # удалить базу и наполнить её заново
```

## Проверка работы

```bash
python -m unittest discover -s tests -t .   # 86 автотестов
python tools/check.py                       # проверка качества кода
python tools/demo.py http://127.0.0.1:8000  # демонстрация всех возможностей
```

## Как устроена авторизация

Пароль хранится только в виде хэша PBKDF2-HMAC-SHA256 с индивидуальной солью.
После входа сервер выдаёт два токена JWT, подписанных алгоритмом HS256:
короткий access-токен (30 минут) для работы и длинный refresh-токен (14 суток)
для получения нового access-токена. Каждый защищённый запрос несёт заголовок
`Authorization: Bearer <токен>`, по которому сервер определяет пользователя и
его роль.

## Статусы задачи

```
новая ──► в работе ──► на проверке ──► завершена
  │           │  ▲           │
  │           └──┘           ├──► отклонена ──► в работе
  └──► отклонена             └──────┘
```

Переходы описаны в файле `app/states.py` таблицей `TRANSITIONS`. Переход,
которого нет в таблице, сервер отклоняет с кодом 403, поэтому испортить
историю задачи нельзя даже при ошибке в клиенте.
